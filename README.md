Jinnie is an offline-first personal finance app for the Philippines, built as a
**super app**. A native host shell downloads independently deployed mini apps
and runs them at runtime. Your financial data stays on your device. There is no
account and no server-side ledger.

**Website:** [jinnie.ph](https://jinnie.ph) · **Course:**
[learn.jinnie.ph](https://learn.jinnie.ph) · **Website source:**

## Highlights

- **Super-app architecture.** Module Federation through Re.Pack. Each mini app
  is its own bundle and can be released without shipping a new binary.
- **Offline-first.** One shared, local ledger that every mini app reads and
  writes through `@jinnie/sdk`.
- **Privacy built in.** A PIN lock, a privacy switch that masks amounts, and
  sealed backups.
- **Bilingual financial literacy.** The Learn course, in English and Filipino,
  runs in a native WebView with a bridge into the app.
- **Typed SDK and UI kit.** A small in-repo component library and icon set,
  with no third-party UI framework.

Fifteen mini apps ship today — **Accounts, Wallet, Bills, Budget, Insights,
Subscriptions, Credit, Learn, Security** (core) and **Goals, Debts, Circles,
Remit, Shared** (community), plus **Settings**, which the shell opens from its
gear rather than listing in the launcher — each its own bundle, each
releasable without shipping a new binary.

The mark is a genie lamp carrying **金** (jīn — gold, wealth).

## Architecture in one paragraph

Every mini app is a [Module Federation](https://module-federation.io) container
built by [Re.Pack](https://re-pack.dev) (Rspack for React Native). The host owns
the binary and every native dependency; mini apps declare them as peers and
consume them as runtime singletons. `@jinnie/sdk` is itself a shared singleton,
which is what makes the Wallet ledger, the privacy switch, and the host bridge
the same objects in every bundle. Native projects are generated by
`expo prebuild`, so the Expo SDK modules are available even though Re.Pack —
not Metro — does the bundling.

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) and [Learn integration](docs/LEARN.md).

Learn embeds the Next.js course at `https://learn.jinnie.ph/` in a native WebView.
The website repository owns its React interface and the data/media in
`jinnie-web/learn`; this repository owns the native wrapper and bridge.
Next.js renders the course directly; its asset pipeline publishes media only.
There is no separate static course application to copy into the native repo.
Set `JINNIE_LEARN_URL` before starting/building the Learn wrapper to use a local
or staging course document. It is separate from the native `JINNIE_CDN`.

## Setup

```powershell
pnpm install
pnpm --filter @jinnie/host prebuild   # generates android/ and ios/
```

`prebuild` runs `expo prebuild --clean`. The generated `android/` and `ios/`
folders are gitignored — regenerate them rather than editing them by hand.

> **pnpm must be on PATH.** Several root scripts shell out to `pnpm` by name.
> `corepack prepare pnpm@11.20.0 --activate` works for direct invocation
> (`corepack pnpm …`) but does not put `pnpm` on PATH without an elevated
> `corepack enable`, and those root scripts will fail. `npm install -g pnpm` is
> the simpler route.

## Running

Start the host and all fifteen mini-app dev servers at once:

```powershell
pnpm start          # mprocs dashboard: cdn 9020, host 8081, mini apps 9001-9015
```

Then, in a second terminal:

```powershell
pnpm --filter @jinnie/host reverse    # Android — see below
pnpm android                          # or: pnpm ios
```

### Android: the ports must be reversed

An emulator cannot reach your machine on `localhost`, and the React Native CLI
only forwards Metro's port. The host resolves fifteen more, so run `reverse` once
per emulator boot or every mini app will fail to load while the shell comes up
fine. `reverse` works the same over USB for a physical device, so `localhost`
stays correct there too. Only a device on Wi-Fi alone needs the LAN IPv4:

```powershell
$env:JINNIE_CDN = "http://192.168.1.20:9020"
```

In that case the first run of each dev server triggers a Windows Firewall
prompt — allow **Private** networks or the device cannot reach them.

## When a change does not show up

Each mini app is served by its own Re.Pack dev server, and the watcher
occasionally misses a write. If a saved change never reaches the device,
restart that app's server (`pnpm --filter @jinnie/<app> start`) and relaunch
the app. To confirm what a server is serving, fetch its expose chunk and look
for a string from your change:
`curl http://localhost:9002/android/__federation_expose_App.chunk.bundle | grep "Record activity"`.

Stopping a server with Task Manager can leave its IPv6 listener behind, so a
restart fails with `EADDRINUSE ::1:<port>`; kill every process on that port
(`netstat -ano | findstr :9002`) before starting it again.

## Release check

`expo prebuild` wires Gradle to Metro; `plugins/withRepackBundleEntry` points
it back at Re.Pack, so `gradlew app:assembleRelease` bundles the host with the
same tool as the dev server. To run that APK against local bundles: build each
app (`pnpm --filter @jinnie/<app> bundle:android`), start
`pnpm --filter @jinnie/host cdn:release`, and install the APK; release builds
allow cleartext to `localhost` only, for exactly this.

## Publishing the apps

`pnpm --filter @jinnie/host cdn:pack` assembles `.build/jinnie-cdn`: `apps.json`,
the Vercel static hosting configuration, and every app's release bundle under
`<app>/<platform>/`. Publish it with:

```powershell
vercel deploy .build/jinnie-cdn --prod --yes --project jinnie-cdn --scope sumnora
```

The current SDK/mini-app origin is `https://sdk.jinnie.ph`, which new release
builds use by default. `https://jinnie-cdn.vercel.app` remains an alias for
installed builds. Manifests cache for a minute and hashed bundles for a year.
The legacy `cdn:upload` command targets R2; do not use it for SDK releases.
Do not use `cdn.jinnie.ph` for SDK bundles; it is reserved for Cloudflare assets.
Publish the website's generated Learn media and screenshots to that asset origin
with `pnpm --filter @jinnie/host assets:upload`. It reads the sibling
`jinnie-web/public` folder by default; pass another public directory as its
argument if needed. The website uses `JINNIE_ASSET_ORIGIN=https://cdn.jinnie.ph`
in production and retains local files for development.
Set `JINNIE_CDN` to point a release check at another origin. Installed copies
pick up a new publish on their next launch. Gradle does not track that variable:
after changing it, run `:app:createBundleReleaseJsAndAssets --rerun-tasks`
before assembling the APK so the compiled origin is refreshed.

## Checks

```powershell
pnpm test        # finance calculations and data-integrity regressions
pnpm typecheck   # every package
```

`pnpm test` runs under plain Node with in-memory storage shims — no device or
emulator needed. It covers the ledger reconciliation, currency conversion,
liability direction, bill reopening, money formatting, backup sealing, the
PIN lock, and every community app's validation path.

GitHub Actions runs the same two commands on every push and pull request,
then builds a release APK with every mini-app bundle
(`.github/workflows/ci.yml`).

## Regenerating the app icons

The launcher, adaptive, and splash icons are rasterised from the lamp mark.
They are committed; regenerate only when the mark or the brand colours change:

```powershell
cd packages/host
npm i -D sharp
node scripts/make-icons.mjs
```

## Stack

React Native 0.86 · React 19 · Expo SDK 57 (modules + prebuild + EAS) ·
Re.Pack 5 / Rspack · Module Federation v2 · React Navigation 7 · Zustand ·
react-native-svg. No UI framework beyond the in-repo library in
`packages/sdk/src/ui`, and no icon package — the set in
`packages/sdk/src/icons` is drawn in-repo.
